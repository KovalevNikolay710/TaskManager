# Профиль и уведомления

Макет: `design/screens/profile.html`. Панель в правом верхнем углу переключает состояния push на этом устройстве (включены, не включены, запрос разрешения, заблокированы, не поддерживается, ошибка подписки), состояния настроек (загрузка, ошибка), Toast после тестового уведомления и тему. Во фронтенд панель не переносить.
Компоненты и форматы описаны в `design/system.md`, значения берутся из `design/tokens.css`, эталонная вёрстка — `design/components.css` (раздел «Быстрая задача, профиль и уведомления»).

Маршрут: `/profile` (сейчас заглушка `ProfilePage` → `StubPage`). Открывается с `AvatarButton` в `AppHeader` (мобильный) и блоком профиля внизу `SideNav` (десктоп).

## Назначение
Включить напоминания. Приложение напоминает утром составить план, вечером — отметить сделанное, а перед дедлайном — что срок близко. Без напоминаний пользователь забывал открывать приложение и в итоге бросил его. Профиля и входа пока нет, поэтому на экране только строка «Пользователь #1».

## Данные

`userId` — `CURRENT_USER_ID` (`web/src/api/user.ts`). Запросы в camelCase, ответы в PascalCase (как во всём API). Все пути — с префиксом `/api`.

Источников два:
1. **Push на этом устройстве** — API браузера, не сервер. Это свойство устройства: на телефоне push может быть включён, а на ноутбуке — нет.
2. **Настройки напоминаний** — сервер, одни на пользователя: `GET /api/notifications/settings/:user_id`. Они общие для всех устройств: напоминание приходит на все устройства, где включён push.

| Что показываем | Источник | Поле / вызов | Формат |
|---|---|---|---|
| Строка пользователя | `CURRENT_USER_ID` | — | аватар «Я», «Пользователь #1», «Вход и синхронизация появятся позже» |
| Поддержка push | браузер | `'serviceWorker' in navigator && 'PushManager' in window && 'Notification' in window` | нет поддержки → состояние «Не поддерживается» |
| Разрешение | браузер | `Notification.permission`: `default` / `granted` / `denied`; изменения — `navigator.permissions.query({name: 'notifications'})` → `onchange` | см. «Состояния push» |
| Подписка устройства | браузер | `(await navigator.serviceWorker.ready).pushManager.getSubscription()` | есть подписка и `granted` → «Включены» |
| Утреннее напоминание | `GET /api/notifications/settings/:user_id` | `MorningEnabled`, `MorningTime` | `Switch` + время «08:00» (`<input type="time">`) |
| Вечернее напоминание | то же | `EveningEnabled`, `EveningTime` | `Switch` + «21:00» |
| «Дедлайн скоро» | то же | `DeadlineEnabled`, `DeadlineHoursBefore` | `Switch` + чипы «1 ч / 3 ч / 6 ч / 12 ч / 24 ч» (radiogroup), по умолчанию 3 |
| Тихие часы | то же | `QuietEnabled`, `QuietFrom`, `QuietTo` | `Switch` + «С [23:00] до [07:00]» (два `<input type="time">`). Действуют только на «Дедлайн скоро» |
| Часовой пояс | то же | `Timezone` | не показывается. Если пусто или отличается от `Intl.DateTimeFormat().resolvedOptions().timeZone`, фронт молча отправляет POST с `timezone` |

Время в настройках — местное время пользователя (`Timezone`), строка `"ЧЧ:ММ"`.

## Компоненты

Из `system.md`: `AppShell`, `AppHeader` (без `AvatarButton`: это и есть профиль), `SectionTitle`, `Input` (`type="time"`, класс `input--time`), `Chip` (radiogroup), `Button` (secondary, загрузка), `Alert` (danger, а также новые варианты **info** и **warning**), `Skeleton`, `Toast`, `BottomNav` (без активного пункта) / `SideNav` (активен блок профиля).

Новые (описаны в `system.md`): **`Switch`**, **`SettingsCard`** (строки настроек), **`ProfileCard`**.

Структура сверху вниз:
1. `AppHeader` «Профиль».
2. `ProfileCard`: аватар 48px «Я», «Пользователь #1», «Вход и синхронизация появятся позже».
3. `SectionTitle` «Уведомления».
4. `SettingsCard`:
   1. **Push-уведомления** (иконка `bell`) + `Switch`. Подпись меняется по состоянию. Под строкой — `Alert` для «заблокированы / не поддерживается / ошибка» и подсказка «Настройки ниже сохранятся, но на это устройство напоминания не придут, пока уведомления выключены» (когда push не включён).
   2. **Утром: составить план** (иконка `sun`), подпись «Если плана на сегодня ещё нет», `Switch`; если включено — «Во сколько [08:00]».
   3. **Вечером: отметить сделанное** (иконка `moon`), «Если в плане дня остались неотмеченные задачи», `Switch`; если включено — «Во сколько [21:00]».
   4. **Дедлайн скоро** (иконка `flag`), «Один раз по каждой невыполненной задаче», `Switch`; если включено — «За [1 ч] [3 ч] [6 ч] [12 ч] [24 ч]».
   5. **Тихие часы** (иконка `bell-off`), подпись «Напоминания о дедлайнах придут после их окончания», `Switch`; если включено — «С [23:00] до [07:00]» (два `input--time`). Под полями подсказка: если «с» позже «до» — «Через полночь: до 07:00 следующего дня», иначе — «С 13:00 до 15:00 того же дня»; если совпадают — ошибка «Начало и конец не могут совпадать» (`field__hint--error`, `input--error` у обоих полей), запрос не отправляется.
   6. Низ карточки: secondary «Отправить тестовое уведомление» (иконка `send`) и подсказка.

Параметр напоминания (время, «за N ч») показывается только при включённом напоминании (`settings__row--off` его прячет). Значение при выключении сохраняется на сервере и возвращается при включении.

**Напоминания доступны, даже когда push на этом устройстве выключен.** Настройки принадлежат пользователю, а не устройству. Ноутбук без push не должен мешать настроить напоминания для телефона. Чтобы было понятно, почему ничего не приходит, под главной строкой видна подсказка.

## Состояния push (это устройство)

| Состояние | Когда | Switch | Подпись и что ещё видно |
|---|---|---|---|
| Включены | `permission = granted` и есть подписка | вкл. | «Включены на этом устройстве» (`--color-success`). Кнопка теста активна |
| Не включены | `permission = default`, или `granted` без подписки | выкл. | «Напомним о плане и дедлайнах, даже когда приложение закрыто» + подсказка про устройство. Тест `disabled`, под ним «Сначала включите push-уведомления» |
| Запрос разрешения | пользователь включил `Switch`, ждём системный диалог и подписку | вкл., `switch--pending` (пульсирует бегунок), `aria-busy` | «Разрешите уведомления в окне браузера…» |
| Заблокированы | `permission = denied` | выкл., `disabled` | «Заблокированы в настройках браузера» + `Alert` warning «Уведомления заблокированы» с двумя путями: «в установленном приложении — долгое нажатие на иконку TaskManager → «О приложении» → «Уведомления»»; «в браузере — значок слева от адреса → «Разрешения» → «Уведомления» → «Разрешить»». Кнопка «Проверить снова». Повторно вызвать системный диалог из страницы нельзя: браузер его больше не покажет |
| Не поддерживается | нет `serviceWorker` / `PushManager` / `Notification` | выкл., `disabled` | «Недоступны в этом браузере» + `Alert` info: «На Android откройте TaskManager в Chrome и установите на главный экран: ⋮ → «Установить приложение». На iPhone уведомления работают только у приложения, добавленного на экран «Домой» (iOS 16.4 и новее).» |
| Ошибка подписки | не удался `GET /api/push/key` (только сеть или сбой сервера: ключи сервер создаёт сам, см. «Требуется от бэкенда»), `pushManager.subscribe` или `POST /api/push/subscribe` | выкл. | `Alert` danger «Не удалось включить уведомления» + текст ошибки (для сети — «Сервер не ответил. Разрешение браузера сохранено — осталось повторить.») + «Повторить» |

## Состояния настроек напоминаний

| Состояние | Когда | Вид |
|---|---|---|
| Загрузка | до ответа `GET /api/notifications/settings` | строка push работает сразу (она от сервера не зависит), вместо трёх строк напоминаний — две skeleton-строки (иконка, две полосы текста, «таблетка» переключателя) |
| Данные | ответ 200 | как в макете |
| Ошибка загрузки | сеть или 5xx | вместо строк напоминаний — `Alert` «Не удалось загрузить напоминания» + текст + «Повторить» |
| Сохранение | после изменения | без спиннера: изменение применяется сразу (оптимистично). Ошибка — откат к прежнему значению и `Toast` «Не удалось сохранить настройку» + «Повторить» |
| Тест отправляется | `POST /api/push/test` в процессе | кнопка: спиннер + «Отправляем…» |
| Тест отправлен | ответ 200 | `Toast` «Отправили. Уведомление придёт в течение минуты» |

## Действия

| Действие пользователя | Что происходит | Результат в UI |
|---|---|---|
| Открыть экран | 1) проверить поддержку, `Notification.permission`, `getSubscription()`; 2) `GET /api/notifications/settings/:userId`; 3) если подписка есть и разрешение `granted` — молча `POST /api/push/subscribe` с той же подпиской (upsert: сервер мог её потерять); 4) если `Timezone` из ответа пуст или отличается от браузерного — `POST /api/notifications/settings/:userId` `{"timezone": "Europe/Moscow"}` | состояние push + данные |
| Включить push (`Switch` → вкл.) | **только в обработчике клика** (иначе браузер не покажет диалог): 1) `Notification.requestPermission()`; 2) при `granted` — `GET /api/push/key` → `{"PublicKey": "BEl6…"}` (кэшировать); 3) `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: base64UrlToUint8Array(PublicKey) })`; 4) `POST /api/push/subscribe`, тело `{"userId": 1, "endpoint": "https://fcm.googleapis.com/fcm/send/…", "keys": {"p256dh": "BN…", "auth": "k8…"}, "userAgent": "<navigator.userAgent>"}` (это `subscription.toJSON()` + `userId`, `userAgent`); 5) `POST /api/notifications/settings/:userId` `{"timezone": "…"}` | «Запрос разрешения» → «Включены». При `denied` → «Заблокированы». Если пользователь закрыл диалог (`default`) → «Не включены», без ошибки. Если упал шаг 4, подписка в браузере остаётся, «Повторить» повторяет только шаг 4 |
| Выключить push | 1) `subscription.unsubscribe()` — сразу; 2) `DELETE /api/push/subscribe`, тело `{"userId": 1, "endpoint": "…"}`. Ошибку шага 2 не показываем: сервер сам удалит подписку, когда push-сервис ответит 404/410 | «Не включены» |
| «Проверить снова» (заблокированы) | перечитать `Notification.permission` | если уже не `denied` — «Не включены» (можно включить) или «Включены», если подписка есть |
| «Повторить» (ошибка подписки) | повторить с упавшего шага | как «Включить push» |
| Переключить напоминание | `POST /api/notifications/settings/:userId`, тело — только изменённое поле: `{"morningEnabled": false}` / `{"eveningEnabled": true}` / `{"deadlineEnabled": true}` | переключатель меняется сразу; поле параметра появляется или скрывается |
| Изменить время | по событию `change` (выбор в нативном пикере завершён): `{"morningTime": "07:30"}` / `{"eveningTime": "22:00"}`. Пустое значение не отправляется: поле возвращается к прежнему | — |
| Выбрать «за N ч» | `{"deadlineHoursBefore": 6}` | чип выбран |
| Переключить «Тихие часы» | `{"quietEnabled": false}` | поля «с/до» появляются или скрываются |
| Изменить «с» или «до» | по `change`: `{"quietFrom": "22:30"}` / `{"quietTo": "08:00"}`. Если новое значение совпало с другим концом интервала — не отправлять: под полями ошибка «Начало и конец не могут совпадать», поле `input--error`; пустое значение возвращается к прежнему | — |
| «Отправить тестовое уведомление» | `POST /api/push/test`, тело `{"userId": 1, "endpoint": "<эндпоинт этого устройства>"}` | `Toast` «Отправили…». Ответ 404 или 410 (подписка потеряна или устарела): подписку в браузере снять, состояние «Не включены», `Toast` «Подписка устарела — включите уведомления заново». Кнопка `disabled`, если push на этом устройстве не включён |
| Нажать на уведомление (в системе) | service worker `notificationclick`: закрыть уведомление; если есть открытое окно приложения — `focus()` и переход на `data.url`; иначе `clients.openWindow(data.url)` | открывается нужный экран |

## Уведомления: тексты и правила

Сервер отправляет в push JSON: `{"title": "…", "body": "…", "url": "/day", "tag": "plan-morning"}`. Service worker показывает его через `showNotification(title, { body, tag, data: { url }, icon: '/icons/icon-192.png', badge: '/icons/badge-96.png', lang: 'ru' })`. Повторное уведомление с тем же `tag` заменяет предыдущее, а не копится.

Все тексты — в местном времени пользователя (`Timezone`), даты и длительности — по «Форматам» из `system.md`.

### 1. Утро: «составь план»
- **Когда:** в `MorningTime` (по умолчанию 08:00), если `MorningEnabled`, **плана на сегодня ещё нет** (нет `Day` с сегодняшней локальной датой) и есть хотя бы одна активная задача. Не чаще раза в день.
- **Заголовок:** «Составьте план на сегодня»
- **Текст:**
  - если у какой-то активной задачи дедлайн сегодня или завтра: «Активных задач: 9. Ближе всего срок у «Подготовить отчёт по ТИПИС» — сегодня, 18:00.»
  - иначе: «Активных задач: 9. Сколько времени готовы отдать делам сегодня?»
- **Нажатие:** `/day`. **tag:** `plan-morning`. **TTL:** 3 ч (если телефон был выключен, утреннее напоминание в обед уже не нужно).

### 2. Вечер: «отметь сделанное»
- **Когда:** в `EveningTime` (по умолчанию 21:00), если `EveningEnabled`, план на сегодня есть и в нём остались задачи со `Status = 1`. Если плана нет или всё отмечено — не отправляется.
- **Заголовок:** «Отметьте, что сделали сегодня»
- **Текст:** первые две задачи плана по `Priority` ↓ и остаток:
  - «В плане осталось 3 из 7: «Подготовить отчёт по ТИПИС», «Пробежка 5 км» и ещё 1.»
  - одна задача: «В плане осталась 1 задача из 7: «Пробежка 5 км».»
  - названия длиннее 40 символов обрезаются с «…».
- **Нажатие:** `/day`. **tag:** `plan-evening`. **TTL:** 2 ч.

### 3. «Дедлайн скоро»
- **Когда:** проверка раз в минуту. Подходит задача со `Status = 1`, у которой `now < DeadLine ≤ now + DeadlineHoursBefore` и уведомление по паре `(TaskId, DeadLine)` ещё не отправлялось. Если дедлайн перенесли, по новому сроку может прийти новое уведомление.
- **Не дёргать сразу после создания:** если задача создана меньше 30 минут назад, уведомление откладывается (на следующих проверках задача ещё попадает в окно). Пользователь только что сам поставил близкий срок — напоминать об этом через минуту бессмысленно.
- **Тихие часы** (если `QuietEnabled`; по умолчанию 23:00–07:00, по `Timezone`): уведомления «Дедлайн скоро», попавшие в интервал `[QuietFrom, QuietTo)`, откладываются до `QuietTo`, если дедлайн к этому времени ещё не прошёл (иначе не отправляются). Интервал может идти через полночь (`QuietFrom > QuietTo`: 23:00–07:00 — это 23:00…23:59 и 00:00…06:59). Утреннее и вечернее напоминания тихие часы не затрагивают: их время пользователь задаёт сам.
- **Заголовок:** название задачи (до 60 символов, дальше «…»): «Подготовить отчёт по ТИПИС»
- **Текст:** «Дедлайн через 2 ч 50 мин — сегодня, 18:00. Осталось ≈ 1:50 работы.»
  - «Осталось» = `TimeForExecution × (100 − PercentOfCompleting) / 100`, округлено до 5 мин, формат `Ч:ММ`;
  - если работы больше, чем времени до срока: «Дедлайн через 2 ч 50 мин — сегодня, 18:00. Работы ≈ 4:00 — больше, чем осталось времени.»
  - «через N»: меньше часа — «через 45 мин», иначе — «через 2 ч 50 мин» / «через 3 ч».
- **Нажатие:** `/tasks/:TaskId`. **tag:** `deadline-<TaskId>`. **TTL:** до `DeadLine`. **Urgency:** `high`.
- **Сводка:** если за одну проверку подошли 3 задачи и больше (например, сразу после включения), отправляется одно уведомление:
  - заголовок «3 дедлайна в ближайшие 3 ч»;
  - текст «Подготовить отчёт по ТИПИС — 18:00, Код-ревью задачи по API — 19:30 и ещё 1»;
  - нажатие — `/all-tasks`, tag `deadline-summary`.

### 4. Тестовое
- **Заголовок:** «Уведомления работают»
- **Текст:** «Так будут приходить напоминания о плане и дедлайнах.»
- **Нажатие:** `/profile`. **tag:** `test`. **TTL:** 5 мин.

## Адаптивность

- < 960px: как в макете. `BottomNav` без активного пункта. В строках настроек параметр (время, чипы) переносится под название, с отступом на ширину иконки. Чипы «за N ч» помещаются в одну строку уже на 360px.
- ≥ 960px: `SideNav`, в котором выделен блок профиля (фон `--color-accent-soft`, `aria-current="page"`). Колонка до 720px. Раскладка строк та же: параметр под названием, по одной строке.

## Требуется от бэкенда

Всё новое. Слои — как везде: handler → service → repository. Ошибки — `{"error": "…"}` через `respondError`.

### Модели

```go
// PushSubscription — подписка одного устройства (браузера) на push.
type PushSubscription struct {
	SubscriptionId int64  `gorm:"primaryKey;autoIncrement"`
	UserId         int64  `gorm:"index;not null"`
	Endpoint       string `gorm:"uniqueIndex;not null"`
	P256dh         string `gorm:"not null"`
	Auth           string `gorm:"not null"`
	UserAgent      string
	CreatedAt      time.Time
	UpdatedAt      time.Time
}

// NotificationSettings — настройки напоминаний пользователя (одна строка на пользователя).
type NotificationSettings struct {
	UserId              int64  `gorm:"primaryKey"`
	MorningEnabled      bool   `gorm:"not null;default:true"`
	MorningTime         string `gorm:"not null;default:'08:00'"` // ЧЧ:ММ, местное время
	EveningEnabled      bool   `gorm:"not null;default:true"`
	EveningTime         string `gorm:"not null;default:'21:00'"`
	DeadlineEnabled     bool   `gorm:"not null;default:true"`
	DeadlineHoursBefore int    `gorm:"not null;default:3"`
	QuietEnabled        bool   `gorm:"not null;default:true"`
	QuietFrom           string `gorm:"not null;default:'23:00'"` // ЧЧ:ММ; начало тихих часов (только для «Дедлайн скоро»)
	QuietTo             string `gorm:"not null;default:'07:00'"` // ЧЧ:ММ; конец; QuietFrom > QuietTo — интервал через полночь
	Timezone            string // IANA, например "Europe/Moscow"; пусто — часовой пояс сервера
	UpdatedAt           time.Time
}
```

```go
type VapidKeys struct {
	Id         int64  `gorm:"primaryKey"` // всегда 1
	PublicKey  string `gorm:"not null"`   // base64url
	PrivateKey string `gorm:"not null"`
	CreatedAt  time.Time
}
```

Ключи `P256dh` и `Auth` в ответах **не отдавать**: подписка в ответе — DTO без них.

### Отправка
- **VAPID-ключи генерируются сервером автоматически.** При старте сервис push: 1) если заданы `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` — использует их (приоритет у окружения, в БД не пишет); 2) иначе читает строку `VapidKeys` из БД; 3) если её нет — генерирует пару (P-256, `webpush.GenerateVAPIDKeys()` из `github.com/SherClockHolmes/webpush-go`), сохраняет и пишет в лог `slog.Info("созданы VAPID-ключи")` (без приватного ключа). `VAPID_SUBJECT` (`mailto:…`) — из окружения, по умолчанию `mailto:admin@localhost`. Генерация — в одной транзакции с проверкой, чтобы два параллельных старта не создали разные ключи.
- **Смена ключей ломает подписки:** если ключи в окружении отличаются от тех, с которыми устройства подписывались, push-сервис будет отклонять отправку (403). Такие подписки удаляются, а тест вернёт 410, и фронт покажет «Не включены». При повторном включении `pushManager.subscribe` с новым ключом падает, если в браузере осталась старая подписка: фронт её снимает (`unsubscribe`) и подписывается заново. Поэтому ключи из БД не перегенерировать без нужды.
- **Планировщик:** горутина с тикером раз в минуту, запускается из `main` и останавливается по контексту. Для каждого пользователя с подписками проверяет правила 1–3 из раздела «Уведомления». Логирование — `slog` (сколько отправлено, ошибки push-сервиса).
- **Без повторов:** таблица `notification_log` (`UserId`, `Kind` — `morning` | `evening` | `deadline`, `TaskId` — для дедлайна, `Key` — локальная дата `YYYY-MM-DD` для утра и вечера, `DeadLine` в RFC3339 для дедлайна, `SentAt`) с уникальным индексом по `(UserId, Kind, TaskId, Key)`. Запись делается до отправки, в одной транзакции с проверкой: при перезапуске сервера повтора не будет.
- **Пропуск:** если сервер был выключен во время `MorningTime` или `EveningTime`, после запуска напоминание отправляется, только пока не истёк его TTL (утро — 3 ч, вечер — 2 ч).
- **Мёртвые подписки:** push-сервис ответил 404 или 410 — подписка удаляется.
- **Заголовки push:** `TTL` — из правил выше; `Urgency: high` у «Дедлайн скоро», у остальных `normal`; `Topic` = `tag` (push-сервис заменит недоставленное уведомление новым).
- Пересчёт `Tl` для текста «через 2 ч 50 мин» делается от `DeadLine` и текущего времени, а не от сохранённого `NumberOfHoursUntilDL`.

### Фронтенд (для полноты; не бэкенд)
Service worker (`web/public/sw.js` или `vite-plugin-pwa`): кэш оболочки приложения для офлайна, обработчики `push` и `notificationclick`; POST-запросы не кэшируются. Манифест и иконки — `design/icons/README.md`.

## Открытые вопросы
1. **Значения по умолчанию — все три напоминания включены.** Тогда для пользователя достаточно одного переключателя «Push-уведомления». Если это слишком навязчиво, по умолчанию можно оставить только «Дедлайн скоро».
2. **Тема оформления.** В `tokens.css` есть принудительная тема `[data-theme]` («переключатель в профиле»), но переключателя на экране нет — в задачу он не входил. Добавить отдельно: строка «Оформление: Как в системе / Светлая / Тёмная».
3. **Кнопка «Установить приложение»** (`beforeinstallprompt`) пригодилась бы в профиле рядом с уведомлениями, если приложение открыто в браузере, а не установлено. В этот макет не вошла.
