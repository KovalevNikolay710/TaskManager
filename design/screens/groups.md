# Группы

Макет: `design/screens/groups.html`. Панель в правом верхнем углу переключает состояния: данные, перетаскивание, размещение без перетаскивания, после переноса (с `Toast`), загрузка, пусто, ошибка, окна «Изменить», «Новая группа» (с ошибками) и «Удаление», тему. Во фронтенд панель не переносить. В макете нажатие на ручку ⋮⋮ группы включает режим размещения, а выбор цели показывает результат переноса.
Компоненты и форматы описаны в `design/system.md`, значения берутся из `design/tokens.css`, эталонная вёрстка — `design/components.css`.

Маршрут: `/groups`.

## Назначение
Настроить области жизни (учёба, работа, дом, хобби) и их важность относительно друг друга. Группы стоят на **лесенке** из 10 ступеней ×1…×10. Ступень — это вес `Pg` в формуле приоритета: чем выше группа, тем выше её задачи в списках и тем больше времени им достаётся в плане дня. На одной ступени может стоять несколько групп. Новую группу можно вставить **между** двумя занятыми ступенями: группы выше сами поднимутся, и не придётся переставлять их по одной.

## Как попасть на экран
Без изменений: на мобильном — icon-кнопка «Группы» в `AppHeader` экрана «Все задачи»; на десктопе — пункт «Группы» в `SideNav`; ещё ссылка «Управлять группами» под `GroupPicker`. `BottomNav` с активным «Все задачи», «назад» ведёт на `/all-tasks`.

## Данные

`userId` — `CURRENT_USER_ID`. Ответы в PascalCase, запросы в camelCase.

Загрузка — два параллельных запроса (оба уже в кэше, если пользователь пришёл с «Все задачи»):
1. `GET /api/groups/user/:userId` → `Group[]` (кэш `queryKeys.groups`).
2. `POST /api/tasks/user/:userId`, тело `{}` → `Task[]` (кэш `queryKeys.tasks`) — для счётчиков. Если запрос упал, счётчики берутся из `Group.Tasks`, а «Без группы» показывается без счётчика.

| Что показываем | Источник | Поле | Формат |
|---|---|---|---|
| Ступень группы | `GET /api/groups/user/:userId` | `Group.GroupPriority` | ступень ×N лесенки. Вес больше 10 (старые данные) показывается на ×10 с подписью «×12» в мета-строке |
| Цвет ступени и группы | — | `GroupPriority` | `--color-weight-{N}` (класс `.w-N`) |
| Название | то же | `Group.Name` | одна строка, многоточие после ~22 символов |
| Счётчик задач | `POST /api/tasks/user/:userId` | задачи с `Task.GroupId = Group.GroupId`; из них со `Status = 2` | «4 задачи · 1 выполнена»; «3 задачи»; «Нет задач» |
| Порядок групп на ступени | — | `Name` (по алфавиту, без учёта регистра) | порядок внутри ступени смысла не несёт: вес у групп одинаковый |
| «Без группы» | `POST /api/tasks/user/:userId` | задачи с `GroupId = 0` или без существующей группы | некликабельная пунктирная карточка на ступени ×1: «Без группы · N задач · всегда ×1». Показывается всегда, когда есть хотя бы одна группа (это точка отсчёта), даже при 0 задач: «Нет задач · всегда ×1» |
| Затронутые задачи | то же | задачи группы со `Status = 1` | число в подсказках `GroupForm`, `ConfirmSheet` и `Toast` |

## Компоненты

Из `system.md`: `AppShell` (с `BottomNav`, активный пункт «Все задачи»), `SideNav` (активный «Группы»), `PageHeader` с ghost-кнопкой «+ Новая группа», **`GroupLadder`** (новый, заменяет `GroupList`/`GroupRow`), **`WeightScale`** (новый, заменяет `Stepper` веса), `Sheet` + `GroupForm`, `ConfirmSheet`, `Alert`, `Button`, `Skeleton`, `EmptyState`, `ErrorState`, `Toast`.

Структура сверху вниз:
1. `PageHeader`: «назад», «Группы», справа ghost «+ Новая группа».
2. Пояснение (`page-intro`): «Чем выше ступень, тем важнее задачи группы: вес ×N умножает их приоритет. Перетащите группу за ⋮⋮ на другую ступень или между двумя занятыми — группы выше сами поднимутся.»
3. `PlaceBanner` — только в режиме размещения.
4. `GroupLadder`: ступени ×10 (сверху) … ×1 (снизу).
5. Подпись `--text-xs` muted: «„Без группы“ всегда стоит на ×1 — это точка отсчёта.»

`Fab` на экране нет.

### Лесенка: устройство
- Строка-ступень: слева «перила» — цветная полоса-ступень (ширина растёт с весом, силуэт лестницы) и «×N»; справа — карточки групп этой ступени (`LadderGroup`) с переносом строк.
- Занятая ступень: высота ≥ 56px, полоса в полном цвете, «×N» цветом `--w-text`. Пустая ступень: высота 36px, полоса с прозрачностью 0.35, без текста; в режимах переноса появляется подпись «свободно». Все 10 ступеней видны всегда, чтобы раскладка не прыгала в момент начала перетаскивания.
- `LadderGroup`: фон `--w-soft`, слева полоска 3px `--w`. Основная часть — кнопка «изменить» (название + мета-строка цвета `--w-text`), справа отдельная кнопка-ручка ⋮⋮ «Переместить» (36px, зона нажатия 44px, `touch-action: none`).

### Перенос: правило вставки между ступенями
- **На ступень** (сбросить на строку ×N или выбрать «Сюда, рядом» / «Поставить на ×N»): группа получает вес N, остальные группы не меняются.
- **Между ступенями k и k+1** (цель есть, только если **обе** ступени заняты другими группами; «Без группы» занимает ×1; если одна из соседних ступеней пустая, того же порядка можно добиться, поставив группу на эту пустую ступень):
  1. Группа встаёт на k+1. Группы со ступени k+1 поднимаются на k+2; если k+2 тоже занята, её группы поднимаются на k+3, и так далее **до первой свободной ступени**. Выше неё ничего не меняется. Сдвигается минимум групп, относительный порядок сохраняется.
  2. Если цепочка упирается в ×10 (от k+1 до ×10 всё занято), пробуем вниз: группа встаёт на k, группы с k опускаются цепочкой до первой свободной ступени (не ниже ×2: ×1 всегда занята «Без группы»).
  3. Если свободной ступени нет ни вверх, ни вниз, вставка невозможна. Цель показывается disabled с подписью «нет свободной ступени»; при перетаскивании линия вставки не подсвечивается, а подсказка у пальца говорит «Нет свободной ступени — поставьте рядом».
  - Перемещаемая группа сначала «снимается» со своей ступени, поэтому её прежнее место считается свободным.
- Пример из макета: «Спорт» (×1) вставляют между ×2 (Работа, Хобби) и ×3 (Учёба). «Спорт» встаёт на ×3; Учёба ×3 → ×4; ×4 занята («Английский») → Английский ×4 → ×5; ×5 свободна — цепочка останавливается. Меняются веса трёх групп.
- Выше ×10 и ниже ×1 целей нет: вес в формуле по-прежнему 1–10.

### Перетаскивание (pointer, мобильный и десктоп)
- Начинается с ручки ⋮⋮: зажать и сдвинуть больше чем на 6px (на мышке — сразу при движении). Долгое нажатие не нужно. Карточка «поднимается» (`ladder-group--lifted`: тень `--shadow-lg`, поворот −1,5°), на старом месте остаётся пунктирный призрак (`--ghost`).
- Цель под пальцем: над строкой ступени — ступень подсвечена `--color-accent-soft`; в полосе ±10px у границы двух занятых ступеней — линия вставки `--color-accent` с плашкой «Вставить на ×3». Группы, которые сдвинутся, уже во время перетаскивания показывают «→ ×4» в мета-строке.
- Отпустили — перенос выполняется (см. «Действия»). Отпустили вне лесенки или нажали Esc — отмена, карточка возвращается на место (`--duration-normal`).
- У края экрана список автопрокручивается. На мобильном во время перетаскивания прокрутка страницы пальцем отключена (`touch-action: none` только на ручке).

### Размещение без перетаскивания (клавиатура, скринридер, «просто тап»)
- Короткий тап (или Enter / Space) по ручке ⋮⋮ включает **режим размещения** для этой группы:
  - над лесенкой — липкая плашка `PlaceBanner` «Куда поставить «Спорт»? Выберите ступень или место между группами» и кнопка «Отмена»;
  - на каждой ступени, кроме текущей, появляется кнопка-цель: «Поставить на ×N» на пустой, «Сюда, рядом» на занятой (пунктир цвета ступени, высота 36px, зона нажатия 44px);
  - между двумя занятыми ступенями — кнопка «Между ×2 и ×3: встанет на ×3, поднимутся: Учёба ×4, Английский ×5». Последствия видны заранее;
  - перемещаемая группа обведена `--color-focus`.
- Фокус переходит на первую цель. Tab / Shift+Tab и ↑/↓ переходят между целями (roving tabindex), Enter выбирает, Esc — отмена (фокус возвращается на ручку).
- Выбор цели выполняет перенос и выходит из режима.

## Действия

| Действие пользователя | Что происходит (эндпоинт, тело запроса) | Результат в UI |
|---|---|---|
| Перенос на ступень N (drag или цель «на ступень») | если N не равен текущему весу: `POST /api/groups/update/:GroupId`, `{"groupPriority": N}` | группа переезжает (FLIP-анимация). Ответ — `Group`, заменить в кэше. Инвалидировать `queryKeys.tasks` и `queryKeys.days`. `Toast` «„Спорт“ теперь ×4» + «Отменить» |

| «Отменить» в `Toast` | `POST /api/groups/reorder` с прежними весами всех затронутых групп | лесенка возвращается, `Toast` «Перенос отменён» |
| Нажатие на карточку группы | открывается `Sheet` «Группа „<Name>“» | фокус в поле «Название» |

Подсказка меняется со значением: «×1 — как у задач без группы» / «Задачи группы будут в N раза важнее задач без группы»; для существующей группы при изменении — «Было ×3. Учёба встанет на одну ступень с „Английским“. Приоритет 3 активных задач группы пересчитается — они поднимутся в списке». | «Сохранить» в Sheet | `POST /api/groups/update/:GroupId`, только изменённые поля: `{"name": "…"}` и/или `{"groupPriority": 4}` | как раньше: Sheet закрывается, карточка в pending до ответа, при смене веса — переезд по лесенке и инвалидация `tasks` и `days` |

| «Создать группу» в Sheet | `POST /api/groups/`, `{"userId": 1, "name": "<trim>", "groupPriority": N}` → 201 `Group` | Sheet закрывается, группа появляется на своей ступени и на 2 с подсвечивается (`--w-soft` → обычный фон), `Toast` «Группа создана» |

| Подтверждение удаления | `DELETE /api/groups/:GroupId` | как раньше. Ступень освобождается, **другие группы не сдвигаются**: пустые ступени допустимы |
| «назад» | — | `history.back()`, без истории — `/all-tasks` |
| «Повторить» | повтор обоих запросов | skeleton → данные |

**Решение: лесенка при создании группы.** В Sheet «Новая группа» полной лесенки нет. Она не помещается в Sheet на мобильном и дублировала бы экран. Вместо неё `WeightScale` показывает, какие ступени уже заняты и кем. Этого хватает, чтобы выбрать место. Если нужна вставка «между», группу создают и затем переносят на лесенке. Тот же `GroupForm` используется на экранах «Новая задача» и «Задача».

## Адаптивность

- < 960px: колонка «перил» 76px, карточки групп переносятся в несколько строк. `Sheet` выезжает снизу. Кнопка «Новая группа» в шапке на ширине < 360px — только иконка «+» с `aria-label`.
- ≥ 960px: `SideNav` с активным «Группы», колонка «перил» 112px, ступени шире (силуэт лестницы заметнее). Hover на карточках и ручках, курсор `grab` / `grabbing`. `Sheet` — диалог 420px.

## Доступность
- Лесенка — `<ol aria-label="Лесенка групп: сверху самые важные">`, каждая ступень — список `aria-label="Ступень ×N"`.
- Ручка: `aria-label="Переместить «Спорт» на другую ступень"`. Для скринридера перетаскивание не нужно: режим размещения полностью его заменяет.
- Результат переноса объявляется через `Toast` (`role="status"`).
- Цвет ступени дублируется числом «×N» везде.

## Требуется от бэкенда

### 1. `POST /api/groups/reorder` — атомарное изменение весов нескольких групп
Нужен для вставки «между»: сдвиг цепочки групп должен примениться целиком или не примениться вовсе. Иначе при сбое посередине группы окажутся в промежуточном порядке, которого пользователь не выбирал.

- Тело:
  ```json
  {"userId": 1, "groups": [{"groupId": 6, "groupPriority": 3}, {"groupId": 1, "groupPriority": 4}, {"groupId": 5, "groupPriority": 5}]}
  ```
  DTO: `GroupReorderRequest{ UserId int64 binding:"required"; Groups []GroupWeight binding:"required,min=1,dive" }`, `GroupWeight{ GroupId int64 binding:"required"; GroupPriority uint64 binding:"required,min=1,max=10" }`.
- Валидация (400): пустой список; повтор `groupId`; вес вне 1–10. 404: любая группа не найдена или принадлежит другому пользователю (ошибка называет `groupId`).
- В **одной транзакции**: для каждой группы обновить `GroupPriority`, у всех её задач обновить `GroupPriorty` и пересчитать `Priority` (та же логика, что в `UpdateGroup`; вынести в общий метод репозитория или сервиса).
- Ответ 200 — полный список групп пользователя (как `GET /api/groups/user/:user_id`), чтобы фронт заменил кэш целиком.
- Логирование: `slog.Info("Веса групп изменены", "userId", …, "groups", n)`.
- Правило вставки считает клиент (ему всё равно нужен предпросмотр), сервер только атомарно применяет список. Сервер не проверяет, что результат совпадает с правилом лесенки: любой набор весов 1–10 допустим.

### 2. Прежние пункты
- **Счётчики вместо полного preload** (`TaskCount`, `DoneCount` в `GET /api/groups/user/:user_id`) — оптимизация, не блокер.
- **Уникальный индекс на название** (гонка при одновременном создании).
