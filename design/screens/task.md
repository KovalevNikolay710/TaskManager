# Задача

Макет: `design/screens/task.html`. Панель в правом верхнем углу переключает состояния: активная, изменена (несохранённые правки), выполнена, загрузка, не найдена, ошибка, Toast ошибки сохранения, окно удаления, тема. Во фронтенд панель не переносить.
Компоненты и форматы описаны в `design/system.md`, значения берутся из `design/tokens.css`, эталонная вёрстка — `design/components.css`.

Маршрут: `/tasks/:taskId`. Открывается нажатием на карточку задачи (`TaskRow`) на экранах «Все задачи» и «День», а также из `Toast` «Задача создана» → «Открыть».

## Назначение
Одна задача целиком: отметить прогресс, поправить срок, объём, группу или описание, закрыть или вернуть в работу, удалить. Здесь же пользователь видит свой приоритет и может ненавязчиво узнать, из чего он складывается.

## Данные

`userId` — `CURRENT_USER_ID`. Все пути с префиксом `/api`. Ответы — PascalCase, запросы — camelCase.

Загрузка:
1. `GET /api/tasks/:taskId` → `Task` (404 `{"error": "Задача не найдена"}`). Если задача уже есть в кэше `queryKeys.tasks` или в `Tasks` какого-либо дня (`queryKeys.days`), экран сразу рисуется из кэша без skeleton, а запрос обновляет данные в фоне.
2. `GET /api/groups/user/:userId` → `Group[]` (кэш `queryKeys.groups`): для `GroupPicker` и названия группы в объяснении приоритета.
3. `POST /api/tasks/user/:userId`, тело `{}` → `Task[]` (кэш `queryKeys.tasks`): только для места в очереди. Если запрос упал, место не показывается, остальное работает.

| Что показываем | Источник | Поле | Формат |
|---|---|---|---|
| Название | `GET /api/tasks/:taskId` | `Task.Name` | `TitleInput`, до 200 символов |
| Статус | то же | `Task.Status` (1 — активна, 2 — выполнена) | 1 → кнопка «Отметить выполненной»; 2 → `StatusBanner` |
| Когда выполнена | то же | `Task.UpdatedAt` | «Отмечена сегодня, 11:05» (формат служебных дат). Поля `CompletedAt` нет, см. «Требуется от бэкенда» |
| Приоритет | то же | `Task.Priority` | `PriorityChip` «16,2»; уровень — относительно максимума `Priority` среди **всех активных** задач пользователя (как на «Все задачи») |
| Место в очереди | `POST /api/tasks/user/:userId` | `Task.Priority`, `Task.Status` | позиция задачи в `sortTasks(tasks)` среди активных: «1-я из 9 активных». Для выполненной не показывается |
| Множители приоритета | `GET /api/tasks/:taskId` | `GroupPriorty` (Pg), `TimeForExecution` (Te), `NumberOfHoursUntilDL` (Tl), `PercentOfCompleting` (%in = (100 − %) / 100) | Берём **серверные** значения, чтобы произведение совпало с показанным `Priority`. Подпись у Tl: «на момент расчёта, <UpdatedAt>» — `Tl` фиксируется при сохранении и со временем устаревает |
| Название группы в объяснении | `GET /api/groups/user/:userId` | `Group.Name` по `Task.GroupId` | «Учёба»; `GroupId = 0` → «без группы» |
| Прогресс | `GET /api/tasks/:taskId` | `Task.PercentOfCompleting` | `PercentSlider`, «40%» |
| Дедлайн | то же | `Task.DeadLine` (RFC3339) | `DeadlineField`: дата и время в локальном поясе + расшифровка «завтра, 10:00 — через 20 ч». Просроченный: «просрочено на 3 ч», danger |
| Время на выполнение | то же | `Task.TimeForExecution` (минуты) | `TimeInput`, «3:00» |
| Группа | то же + группы | `Task.GroupId` ↔ `Group.GroupId` | `GroupPicker`, выбран чип группы или «Без группы» |
| Описание | то же | `Task.Description` | `Textarea`, placeholder «Детали, ссылки, что именно сдать» |
| Служебная строка | то же | `Task.CreatedAt`, `Task.UpdatedAt` | «Создана 20 сентября, 09:12 · изменена вчера, 21:40» |

## Компоненты

Из `system.md`: `AppShell` (на мобильном без `BottomNav`), `SideNav`, `PageHeader`, `TitleInput`, `Button` (secondary, danger-ghost, загрузка), `StatusBanner`, `PriorityCard`, `PriorityChip`, `Badge`, `FormCard`, `PercentSlider`, `DeadlineField`, `TimeInput`, `GroupPicker` + `GroupForm` в `Sheet`, `Textarea`, `MetaNote`, `ActionBar`, `ConfirmSheet`, `Alert`, `Toast`, `Skeleton`, `EmptyState`, `ErrorState`.

Новые для этого экрана: `TitleInput`, `StatusBanner`, `PercentSlider`, `PriorityCard`, `MetaNote`, `ConfirmSheet`, `Button` danger / danger-ghost. Общие с «Новой задачей»: `PageHeader`, `FormCard`, `DeadlineField`, `GroupPicker`, `ActionBar`, `Alert`.

Структура сверху вниз:
1. `PageHeader`: «назад» и «Задача».
2. `TitleInput` с названием.
3. Статус: кнопка «Отметить выполненной» или `StatusBanner`.
4. `PriorityCard`.
5. `FormCard` «Выполнено» с `PercentSlider`.
6. `FormCard` «Срок и объём»: `DeadlineField` (без пресетов: при редактировании они скорее мешают), `TimeInput` (без пресетов).
7. `FormCard` «Группа»: `GroupPicker`.
8. `FormCard` «Описание»: `Textarea`.
9. `MetaNote`.
10. danger-ghost «Удалить задачу».
11. `ActionBar` «Отменить» / «Сохранить», только если есть несохранённые изменения.

Прогресс стоит выше сроков, потому что его меняют чаще всего.

**Модель редактирования.** Экран не делится на «просмотр» и «редактирование»: поля сразу редактируемые, но выглядят спокойно (название — как заголовок). Любое отличие от последней серверной версии делает форму «изменённой» и показывает `ActionBar`. Сохраняется всё одной кнопкой. Исключения, которые отправляются сразу: «Отметить выполненной», «Вернуть в работу» и удаление.

## Состояния

| Состояние | Когда | Вид |
|---|---|---|
| Загрузка | задачи нет в кэше, ждём `GET /api/tasks/:taskId` | skeleton: полоса заголовка, кнопка, 3 карточки. `PageHeader` виден сразу |
| Активная | `Status = 1` | как в макете (кнопка «Отметить выполненной», `PriorityCard` с числом и местом) |
| Изменена | значения формы отличаются от серверных | `ActionBar` выезжает снизу; в `PriorityCard` плашка «После сохранения ≈ 12,6 → 2-я из 9» (пересчёт на клиенте по новым `Pg`, `Te`, `Tl = floor((deadline − now) / 1 ч)`, `%`). Выход с экрана — через `ConfirmSheet` «Выйти без сохранения?» |
| Сохранение | запрос update в процессе | «Сохранить» — спиннер + «Сохраняем…», поля disabled, «Отменить» неактивна |
| Ошибка сохранения | update вернул ошибку | правки остаются, `ActionBar` остаётся, `Toast` над панелью: «Не удалось сохранить изменения» + «Повторить». Ошибка валидации дедлайна от сервера — текстом под полем (как в «Новой задаче») |
| Выполнена | `Status = 2` | `StatusBanner` «Выполнена · Отмечена сегодня, 11:05» + «Вернуть в работу»; название приглушено (`--color-text-muted`), `PriorityCard` в варианте done (`Badge` «0», «Выполненные задачи не участвуют в очереди…»), `PercentSlider` disabled на 100% с подсказкой. Остальные поля редактируются |
| Смена статуса в процессе | запрос status в процессе | нажатая кнопка в состоянии загрузки («Отмечаем…» / «Возвращаем…»), вторая не показывается |
| Не найдена | 404 или `taskId` не число (бэкенд отвечает 400) | `EmptyState` с иконкой лупы: «Задача не найдена» / «Возможно, её уже удалили или ссылка устарела.» / primary «К списку задач» (→ `/all-tasks`) |
| Ошибка | сеть или 5xx при загрузке, кэша нет | `ErrorState` «Не удалось загрузить задачу», текст ошибки мелко, «Повторить». Если кэш есть — показываем кэш, а ошибку фонового обновления — `Toast` |
| Удаление | открыт `ConfirmSheet` | см. «Действия» |

Валидация полей — как в `new-task.md` (название не пустое, дедлайн не раньше чем через час, время 0:05–99:59). Исключение: если дедлайн **не меняли**, а он уже прошёл или ближе часа, это не ошибка. Поле показывает «просрочено на 3 ч» в danger, и сохранение других полей не блокируется.

## Действия

Все обновления — `POST /api/tasks/update/:taskId`, ответ 200 — обновлённый `Task`. После **любого** успешного ответа:
- заменить задачу объектом из ответа в `queryKeys.tasks` и во всех `Day.Tasks` в `queryKeys.days` (так же, как в `useToggleTask`);
- сбросить форму к значениям из ответа (форма больше не «изменена»);
- `PriorityCard` показывает новое `Priority` и место.

| Действие пользователя | Что происходит (эндпоинт, тело запроса) | Результат в UI |
|---|---|---|
| Правка любого поля | — | форма «изменена», появляется `ActionBar`, в `PriorityCard` — прогноз |
| Слайдер / шаги процента | — | значение 0–100 с шагом 5; на 100% подсказка «При сохранении задача станет выполненной» |
| «Сохранить» / Ctrl+Enter | валидация, затем тело **только из изменённых полей**: `{"name": "…", "description": "…", "deadline": "<RFC3339>", "timeForExecution": 210, "percentOfCompleting": 60, "groupId": 2}` | `Toast` «Сохранено» (2 с). Если отправлен `percentOfCompleting: 100`, бэкенд ставит `Status = 2`, и экран переходит в «Выполнена» |
| «Отменить» в `ActionBar` | — | форма возвращается к серверным значениям, `ActionBar` скрывается |
| «Отметить выполненной» | `{"status": 2}` + изменённые поля, если они есть (одним запросом, чтобы правки не потерялись) | «Выполнена». Задача уходит вниз своей группы на «Все задачи» |
| «Вернуть в работу» | `{"status": 1}` + изменённые поля. Бэкенд сбрасывает `PercentOfCompleting` со 100 в 0 или берёт переданный процент от 1 до 99 | «Активная», слайдер снова доступен, приоритет пересчитан |
| Выбор другой группы | входит в «Сохранить» как `groupId` (0 — без группы) | прогноз пересчитывается с `GroupPriority` новой группы (для «Без группы» — 1) |
| «+ Новая группа» | `POST /api/groups/` (как в `new-task.md`) | новая группа выбрана, форма «изменена» |
| «Из чего складывается» | — | раскрывается разбор множителей; состояние запоминается в `localStorage` `tm.priorityExplained` |
| «Удалить задачу» | открывается `ConfirmSheet`: «Удалить задачу?» / «„<Name>“ удалится вместе с прогрессом и пропадёт из плана на день. Отменить это нельзя.» / «Отмена» (фокус) и «Удалить» (danger) | — |
| «Удалить» в `ConfirmSheet` | `GET /api/tasks/delete/:taskId` (после перевода API — `DELETE /api/tasks/:taskId`) → 200 `{"message": "..."}` | задача удаляется из `queryKeys.tasks` и из всех `Day.Tasks`, затем `history.back()` (без истории — `/all-tasks`) и `Toast` «Задача удалена». Ошибка — `Alert` внутри Sheet, Sheet остаётся открытым |
| «назад» | если форма изменена — `ConfirmSheet` «Выйти без сохранения?» / «Изменения в задаче пропадут.» / «Остаться» и «Выйти» (danger) | `history.back()`, без истории — `/all-tasks` |
| «К списку задач» (не найдена) | — | `/all-tasks` |
| «Повторить» (ошибка) | повтор `GET /api/tasks/:taskId` | skeleton → данные |

Обновление данных: при возврате на вкладку (`visibilitychange`) перезапросить `GET /api/tasks/:taskId`, но только если форма не изменена, чтобы не затереть правки.

## Адаптивность

- < 960px: как в макете. `BottomNav` нет. `ActionBar` закреплён внизу, кнопки поровну. `Toast` поднимается над `ActionBar`. `StatusBanner`: если не помещается, кнопка «Вернуть в работу» переносится под текст.
- ≥ 960px: `SideNav` с активным «Все задачи», колонка до 720px. `ActionBar` прилипает к низу колонки (подпись «Есть несохранённые изменения» слева, кнопки справа). `ConfirmSheet` — диалог 420px. Название задачи — `--text-xl`, как на мобильном: это содержимое, а не заголовок раздела.

## Требуется от бэкенда

Пункты 1–4 блокируют экран в заявленном виде. Developer реализует их вместе с экраном (навык `add-endpoint` / правка существующего обработчика).

1. **`name` в `TaskUpdateRequest`.** Сейчас название задачи изменить нельзя. Непустая строка после trim — заменить `Task.Name`.
2. **`groupId` в `TaskUpdateRequest`.** Смена группы: `Task.GroupId`, `Task.GroupPriorty` (= `Group.GroupPriority` новой группы или 1 для `groupId = 0`), связь в `group_tasks` (удалить старую, добавить новую) в одной транзакции, с проверкой владельца группы, пересчётом `Priority`. Нужно различать «не передан» и «0 — убрать из группы» (указатель `*int64`).
3. **Сброс процента в 0.** `percentOfCompleting: 0` сейчас игнорируется (`if input.PercentOfCompleting > 0`), поэтому активной задаче нельзя вернуть 0%. Нужно `*int`: `nil` — не менять, 0–100 — установить (100 → `Status = 2`).
4. **Пересчёт `NumberOfHoursUntilDL` при обновлении.** `UpdateTask` меняет `DeadLine`, но не пересчитывает `Tl`, и приоритет считается по старому сроку. Нужно пересчитывать `Tl` от текущего времени при **каждом** обновлении, тогда прогноз на клиенте совпадёт с ответом. Дедлайн в прошлом сейчас молча игнорируется; должен быть 400 «неверный дедлайн».
5. **Очистка описания.** `description: ""` игнорируется, стереть описание нельзя. Нужен `*string`.
6. **`CompletedAt`.** «Отмечена …» сейчас берётся из `UpdatedAt`, который меняется при любой правке выполненной задачи. Желательно поле `CompletedAt` (ставится при `Status = 2`, сбрасывается при возврате).
7. **Удаление.** Перевести на `DELETE /api/tasks/:id` (как планировалось). Проверить, что удаляются связи в `day_tasks` и `group_tasks`: иначе удалённая задача останется в плане дня или сломает FK. Проверить, что `GenericService[*models.Task].Delete` действительно удаляет: `new(T)` там — `**models.Task`. Для несуществующей задачи отвечать 404.
8. **Ошибки обновления — 400/404, а не 500.** «задача с ID N не найдена» сейчас приходит как 500.
9. Общие пункты из `all-tasks.md`: актуализация `Priority` со временем (пересчёт при выдаче) и сортировка на сервере.
