# Быстрая задача (QuickAddSheet)

Макет: `design/screens/quick-add.html`. Панель в правом верхнем углу переключает состояния: пусто, заполнено, «Другое…» у срока и у времени, раскрытая группа, отправка, успех (серия), ошибка, офлайн, «лист закрыт + Toast», экранная клавиатура (серый блок, только на ширине < 960px) и тема. Во фронтенд панель и блок клавиатуры не переносить.
Компоненты и форматы описаны в `design/system.md`, значения берутся из `design/tokens.css`, эталонная вёрстка — `design/components.css` (раздел «Быстрая задача…»).

Это не отдельный маршрут, а нижний лист поверх экранов «Все задачи» и «День». Полная форма `/tasks/new` остаётся и открывается из листа кнопкой «Подробнее».

## Назначение
Записать задачу за одно действие: ввести название и нажать Enter. Срок, время на выполнение и группа уже выбраны по умолчанию, поменять их можно одним тапом по чипу. Лист рассчитан на серию: после добавления он не закрывается, поле очищается и сразу готово к следующей задаче.

Почему так: пользователь бросил приложение, потому что ввод в полной форме (пять полей, два нативных пикера) занимал слишком много времени. Здесь минимальный путь — **Fab → название → Enter**: один тап и набор текста.

## Как открыть и закрыть

| Откуда | Что открывает |
|---|---|
| `Fab` «+» на «Все задачи» (мобильный) | лист. **Fab больше не ведёт на `/tasks/new`** |
| `Fab` «+» на «День» (мобильный) | лист. Раньше на «Дне» не было `Fab`, теперь он есть (см. `day.md`) |
| Кнопка «Новая задача» в `AppHeader` (десктоп) на «Все задачи» и «День» | тот же лист в виде диалога |
| Клавиша `N` (десктоп; проверять `event.code === 'KeyN'`, чтобы работала и русская раскладка), если фокус не в поле ввода и не открыт другой Sheet | лист |
| `EmptyState` «Добавить задачу» («Все задачи») и «Новая задача» (пустой план на «Дне») | лист |
| Адрес `/all-tasks?quick=1` или `/day?quick=1` (ярлык PWA «Быстрая задача», см. `design/icons/README.md`) | экран и сразу лист |
| «Подробнее» в листе | `/tasks/new` с переносом введённого (см. «Действия») |

**История и кнопка «Назад» на Android.** При открытии листа добавляется запись в историю: `?quick=1` в URL текущего экрана (push). Системный «Назад» закрывает лист, а не уводит с экрана. Закрытие кнопкой ×, тапом по подложке, свайпом вниз или Esc вызывает `history.back()`. Если экран открылся сразу с `?quick=1` (ярлык), при закрытии параметр убирается через `replace`.

**Закрытие без подтверждения.** Если в поле что-то введено, лист закрывается без `ConfirmSheet`: текст сохраняется в черновик и вернётся при следующем открытии (см. «Черновик»). Лишний вопрос — та самая лишняя секунда, из-за которой пользователь бросил приложение.

## Данные

`userId` — `CURRENT_USER_ID` (`web/src/api/user.ts`). Ответы приходят в PascalCase, запросы отправляются в camelCase.

Лист сам ничего не загружает при открытии: он берёт данные из кэша, общего с экранами.
- `GET /api/groups/user/:userId` → `Group[]` (`queryKeys.groups`). Нужен для группы по умолчанию и для `GroupPicker`. Если кэша нет (например, лист открыт с «Дня»), запрос отправляется при открытии.
- `POST /api/tasks/user/:userId`, тело `{}` → `Task[]` (`queryKeys.tasks`). Нужен только для строки предпросмотра «встанет N-й из M». Если запрос не удался, строка показывает только число приоритета.

| Что показываем | Источник | Поле / правило | Формат |
|---|---|---|---|
| Чипы срока | `deadlinePresets(now)` из `web/src/lib/taskForm.ts` | `label`, `date`, `time` | «Сегодня, 21:00» (только до 20:00), «Завтра, 18:00», «Через 3 дня», «Через неделю», затем «Другое…». У «Через 3 дня» и «Через неделю» в `title` — полная дата: «чт, 8 октября, 18:00» |
| Срок по умолчанию | `defaultDeadlinePreset(now, presets)` — пишет пользователь (учебная задача), см. «Срок по умолчанию» ниже | возвращает один из `presets` | ровно один выбранный чип (`aria-checked="true"`) |
| Чипы времени | константа `QUICK_TIME_PRESETS = [15, 30, 60, 120]` | минуты | «15 мин», «30 мин», «1:00», «2:00», затем «Другое…». `aria-label`: «15 минут», «30 минут», «1 час», «2 часа» |
| Время по умолчанию | — | **30 мин** | выбранный чип |
| Группа по умолчанию | `localStorage` `tm.lastGroupId` (`readLastGroupId()` в `web/src/lib/storage.ts`) | группа существует в `Group[]` → она; иначе «Без группы» (`groupId = 0`) | `GroupToggle`: точка цвета веса, название (обрезка с многоточием), «×3», шеврон |
| Список групп при смене | `Group[]` | порядок как в `GroupPicker`: `GroupPriority` ↓, затем `Name`; затем «Без группы» | `ChipRow` с иконкой папки |
| Предпросмотр приоритета | вычисляется на клиенте, как в `new-task.md` («Предпросмотр приоритета») | `Pt = Pg × Te ÷ Tl × 1` | `PriorityIndicator`-чип «3,3» + «встанет 5-й из 12». Уровень цвета считается относительно `max(Priority активных, Pt)` |
| Строка успеха | ответ `POST /api/tasks/` | `Task.TaskId`, `Task.Name`, `Task.Priority` | «**5-я из 12** — «Повторить билеты 1–10 к коллоквиуму»» + «Открыть» |

### Срок по умолчанию: контракт и рекомендация

**Контракт (на нём держится спецификация).** При открытии листа выбран ровно один чип срока — тот, что вернула функция
`defaultDeadlinePreset(now: Date, presets: DeadlinePreset[]): DeadlinePreset`. Она возвращает один из элементов `presets` (то есть `deadlinePresets(now)`) и никогда не возвращает «Другое…». Больше спецификация от функции ничего не требует.

**Функцию пишет пользователь сам — это учебная задача.** Разработчик подключает её по контракту: на время, пока её нет, — заглушка, которая возвращает «Завтра, 18:00» (этот чип есть всегда). Итоговое правило может отличаться от рекомендации ниже, и это не меняет ничего в листе. Тесты на правило выбора пишутся вместе с функцией, а не по этой спецификации.

Поведение листа вокруг функции (от правила не зависит):
- функция вызывается при каждом открытии листа: между открытиями выбор не запоминается. Внутри одной серии (лист открыт, задачи добавляются одна за другой) остаётся чип, выбранный последним;
- если выбранный чип исчез, пока лист открыт (например, «Сегодня, 21:00» после 20:00), выбирается результат `defaultDeadlinePreset(now, presets)` для нового списка. Чипы пересчитываются раз в минуту (`useNow`);
- в макете по умолчанию выбран «Завтра, 18:00» — это лишь пример.

**Рекомендация дизайнера** (не требование):
1. С 00:00 до 04:59 — «Сегодня, 21:00»: ночью «завтра» для человека — это уже наступивший календарный день, и подпись «Сегодня» показывает это честно.
2. В остальное время — «Завтра, 18:00».

Почему не «сегодня» по умолчанию: при `Tl` около 20–40 ч новая задача встаёт в середину списка и не вытесняет настоящие срочные дела. Если по умолчанию стоял бы «сегодня», каждая быстрая задача из-за маленького `Tl` оказывалась бы наверху, и сортировка по приоритету потеряла бы смысл.

Для разработчика: чтобы и функции, и листу не сравнивать подписи, стоит добавить в `DeadlinePreset` поле `id: 'today' | 'tomorrow' | 'in3days' | 'inWeek'`. Подписи и даты не менять: их используют `DeadlineField` и тесты.

### Черновик
- Ключ `localStorage` `tm.quickAddDraft`: `{ name, deadline: { presetId } | { date, time }, minutes, groupId, savedAt }`. Записывается при вводе (debounce 300 мс) и при закрытии листа, если в названии что-то есть.
- При открытии: если черновику меньше 24 ч, название и выбор восстанавливаются. `presetId` пересчитывается в дату по `deadlinePresets(now)`, а если такого чипа уже нет — выбирается `defaultDeadlinePreset(now, presets)`. Свой срок (`date` + `time`) восстанавливается, только если он ещё валиден (≥ now + 1 ч), иначе — `defaultDeadlinePreset(now, presets)`.
- Черновик удаляется после успешного создания задачи и при переходе по «Подробнее» (данные уходят в URL).

## Компоненты

Из `system.md`: `Sheet` (вариант `sheet--quick`), `Input`, `Chip`, `DeadlineField` (только ряд «дата + время» и расшифровка, без своих чипов), `TimeInput`, `GroupPicker` (в виде `ChipRow`, без «+ Новая группа» и без подсказки), `PriorityIndicator` (чип), `Button` (primary, ghost, icon, загрузка), `Alert`, `Toast`, `Fab`.

Новые (описаны в `system.md`): **`QuickAddSheet`**, **`ChipRow`**, **`GroupToggle`**, **`Notice`**.

Структура листа сверху вниз:
1. Ручка (только мобильный).
2. Шапка: «Новая задача» (`--text-lg` semibold), ghost «Подробнее →», icon-кнопка «×».
3. Плашка — не больше одной: офлайн (`Notice`) > ошибка (`Alert`) > успех (`quick-add__status`). Плашка стоит над полем, чтобы её не закрывала клавиатура.
4. Поле названия: `Input` высотой 48px, `--text-lg` medium, placeholder «Что нужно сделать?», `autofocus`, `enterkeyhint="send"`, `maxlength=200`, `autocapitalize="sentences"`.
5. `ChipRow` «Дедлайн» (иконка `flag`) + раскрытие «Другое…»: `DeadlineField` (дата и время) и расшифровка.
6. `ChipRow` «Время на выполнение» (иконка `clock`) + раскрытие «Другое…»: `TimeInput`.
7. `ChipRow` «Группа» (иконка `folder`) — только когда раскрыт `GroupToggle`.
8. Строка предпросмотра: чип приоритета + «встанет 5-й из 12». На десктопе в ней же подсказка «· Enter добавить · Esc закрыть».
9. Низ: `GroupToggle` слева, primary «Добавить» справа (min-width 128px).

Процент выполнения и описание здесь не спрашиваются. Описание добавляется через «Подробнее» или потом на экране задачи.

### Фокус и клавиатура (важно для Android)
- При открытии фокус ставится в название, экранная клавиатура открывается сразу.
- Тап по любому чипу **не уводит фокус из поля**: у чипов `onPointerDown={e => e.preventDefault()}`. Иначе фокус перейдёт на кнопку, клавиатура закроется, а лист прыгнет вниз. Навигация с клавиатуры не ломается: Tab переходит к рядам, внутри ряда работают стрелки ←/→ (roving tabindex, как в `GroupPicker`).
- Исключение — раскрытия «Другое…»: фокус переходит в поле даты или в `TimeInput`, потому что дальше нужен ввод в них.
- Во время отправки поле получает `readOnly`, а **не** `disabled`: `disabled` снимает фокус и закрывает клавиатуру.
- Лист стоит над клавиатурой: в `web/index.html` в `<meta name="viewport">` добавить `interactive-widget=resizes-content` (Chrome на Android 108+). Запасной вариант для других браузеров — слушать `visualViewport.resize` и поднимать лист на `innerHeight − visualViewport.height`.
- Высота листа в свёрнутом виде около 310px. На телефоне 360×740 с клавиатурой (~260–300px) лист помещается целиком. Если раскрыты два ряда сразу, лист прокручивается внутри: `max-height: calc(100dvh − 24px)`.

Когда оба поля заполнены и валидны, подпись чипа меняется на значение «пт, 9 окт, 12:00». Валидация — как у `DeadlineField`: ошибка под полями, «Добавить» `disabled` |
| Время: «Другое…» | тап по «Другое…» | чип выбран и раскрыт, под рядом `TimeInput` (0:05–99:59), подпись чипа — значение «3:30». Ошибка формата — под полем, «Добавить» `disabled` |
| Группа раскрыта | тап по `GroupToggle` | над строкой предпросмотра появляется `ChipRow` групп, выбранная прокручена в зону видимости. Выбор группы сворачивает ряд и обновляет `GroupToggle` и предпросмотр |
| Группы загружаются | нет кэша групп | `GroupToggle` — skeleton-чип шириной 96px. «Добавить» работает и отправляет `tm.lastGroupId`; после загрузки выбор проверяется по списку |
| Группы: ошибка | `GET /api/groups/user` не удался | `GroupToggle` показывает «Без группы» и отправляется `groupId: 0`: что видно, то и уйдёт. В раскрытом ряду — «Не удалось загрузить группы» + ghost «Повторить» |
| Отправка | `POST /api/tasks/` в процессе | название `readOnly` (opacity 0.6), чипы `disabled`, кнопка — спиннер и «Добавляем…». Повторный Enter игнорируется. Закрыть лист можно: запрос не отменяется, результат придёт в `Toast` |
| Успех | ответ 201 | лист **остаётся открытым**. Название очищается, фокус остаётся в поле, клавиатура не закрывается. Срок, время и группа сохраняют выбор (серия обычно однотипная). Над полем — строка успеха (фон `--color-success-soft`, иконка `check-circle`): «**5-я из 12** — «…»» и ghost «Открыть». Следующий успех заменяет строку. Новая карточка появляется в списке под листом (подсветка `--color-accent-soft`, гаснет за 1,5 с) |
| Ошибка сервера | ответ не 2xx или сеть при `navigator.onLine = true` | `Alert` над полем: «Не удалось добавить задачу» + текст (таблица ниже). Фокус **не** переносится на `Alert` (иначе закроется клавиатура): он объявляется через `role="alert"`. Всё введённое остаётся |
| Офлайн | `navigator.onLine === false` или событие `offline` | `Notice` с иконкой `wifi-off`: «**Нет сети.** Добавить задачу получится, когда связь вернётся. Текст не пропадёт.» Поля работают, «Добавить» `disabled`, черновик пишется. По событию `online` плашка исчезает, кнопка становится активной. **Сама задача не отправляется** — пользователь нажимает «Добавить», когда видит, что связь есть |
| Закрыт после серии | лист закрыт, создано N ≥ 1 задач | `Toast` (см. «После закрытия») |

### Ошибки сервера

| Ответ | Что показываем |
|---|---|
| сеть (`status = 0`) | «Не удалось добавить задачу» / «Сервер не ответил. Всё введённое на месте — нажмите «Добавить» ещё раз.» |
| 400 или 500, текст содержит «дедлайн» или «дата» (срок успел стать ближе часа) | вместо `Alert` под рядом срока: «Срок уже слишком близко — выберите другой». `aria-invalid` на ряду; выбор сам не переключается — пользователь выбирает другой чип |
| 400 (ошибка привязки) | «Сервер не принял данные» + текст из `error` |
| прочие | «Не удалось добавить задачу» + текст из `error` |

### «Подробнее»: перенос в полную форму
Через query-параметры `/tasks/new`. Они переживают перезагрузку страницы, и на них же может вести ярлык PWA:

| Параметр | Пример | Откуда |
|---|---|---|
| `name` | `name=Повторить%20билеты` | название (trim); пустое не передаётся |
| `date` | `date=2026-10-06` | дата выбранного срока, `YYYY-MM-DD` |
| `time` | `time=18:00` | время выбранного срока, `HH:MM` |
| `te` | `te=30` | минуты |
| `groupId` | `groupId=3` | `0` — без группы |

`NewTaskPage` (`/tasks/new`) — **изменение для разработчика**:
- начальные значения формы берутся из параметров, каждый проверяется отдельно: невалидный параметр игнорируется, и поле остаётся пустым или со значением по умолчанию. `te` переводится в `Ч:ММ` через `formatDuration`. `groupId`, которого нет в списке групп, даёт «Без группы»;
- если пришло `name`, фокус ставится в «Описание», иначе — в «Название»;
- перенесённые значения считаются введёнными данными: при уходе из формы спрашивается «Выйти без сохранения?»;
- после создания задачи через полную форму всё работает как раньше (`new-task.md`, «После сохранения»).

### После закрытия
Считается, сколько задач создано за время, пока лист был открыт (`N`):

| Экран | N = 1 | N > 1 |
|---|---|---|
| «Все задачи» | `Toast` «Задача создана» + «Открыть» (→ `/tasks/:TaskId`) | `Toast` «Добавлено 3 задачи» + «Показать»: прокрутить к первой новой карточке и снова подсветить все новые |
| «День» | `Toast` «Задача создана» + «В план» | `Toast` «Добавлено 3 задачи» + «В план» |

«В план» открывает `Sheet` «Изменить план» (`day.md`). Действие показывается, только если на выбранную дату (сегодня или будущую) план уже есть. Подсказка «Ещё N задач не в плане» в `DayChart` появится и без этого: кэш задач обновлён.
`N = 0` — `Toast` не показывается.

## Адаптивность

- **Мобильный (< 960px)**: нижний лист на всю ширину, `--radius-lg` сверху, ручка. Ряды чипов не переносятся, а прокручиваются по горизонтали. Ряд уходит под правый край листа, справа затухание 32px — так видно, что чипов больше. При прокрутке до конца затухание пропадает (`chip-row--end`). При открытии выбранный чип прокручивается в зону видимости (`scrollIntoView({inline: 'nearest'})`). `BottomNav` и `Fab` закрыты подложкой.
- 360px: в ряду срока видны «Сегодня, 21:00», «Завтра, 18:00» и часть третьего чипа. В ряду времени — «15 мин», «30 мин», «1:00», часть «2:00». 412px: ряд времени помещается почти целиком.
- **Десктоп (≥ 960px)**: диалог шириной `--size-quick-sheet` (520px), прижат к верху (`padding-top: 12vh`, класс `sheet-backdrop--top`), чтобы не прыгал при раскрытии рядов. Ручки нет. Чипы переносятся на новую строку, прокрутки нет. В строке предпросмотра — подсказка `Enter` / `Esc` (`kbd`). Открывается кнопкой «Новая задача» в `AppHeader` или клавишей `N`.
- `prefers-reduced-motion`: лист появляется без выезда (только opacity), подсветка новой карточки без затухания.

## Требуется от бэкенда

Ничего нового. Используется `POST /api/tasks/` с теми же полями, что у полной формы.
Остаётся в силе п. 6 из `new-task.md`: с несуществующей группой задача молча создаётся без группы. До исправления фронт сверяет `Task.GroupId` в ответе с выбранной группой.

## Открытые вопросы
1. **Очередь офлайн-задач.** Сейчас без сети задачу добавить нельзя, сохраняется только черновик. Можно складывать задачи в очередь (IndexedDB + Background Sync, в Chrome на Android поддерживается) и отправлять при появлении связи. Но приоритет и место в очереди тогда неизвестны до синхронизации. Решение отложено.
2. **Запоминать срок между открытиями?** Сейчас — нет: при каждом открытии вызывается `defaultDeadlinePreset`. Если правило пользователя будет учитывать прошлый выбор, ему понадобится хранилище — договориться о ключе `localStorage` вместе с функцией.
