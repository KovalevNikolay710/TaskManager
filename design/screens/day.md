# Задачи на день

Макет: `design/screens/day.html` (панель в правом верхнем углу переключает состояния макета: данные, перегруз, плана нет, план пуст, загрузка, ошибка, окно «Изменить план», тема; во фронтенд её не переносить).
Компоненты и форматы описаны в `design/system.md`, значения берутся из `design/tokens.css`, эталонная вёрстка — `design/components.css`.

## Назначение
Короткий план на сегодня: сколько задач и времени пользователь готов взять и какие именно задачи приложение выбрало по приоритету. Это стартовый экран приложения: открыл, увидел, что делать первым, отметил выполненное.

## Данные

`userId = 1` — константа фронтенда (`VITE_USER_ID`), как на экране «Все задачи».
Маршрут фронтенда: `/day` (сегодня) и `/day?date=YYYY-MM-DD` (другой день). Корень `/` ведёт на `/day`.

Загрузка — два параллельных запроса:
1. `GET /days/user/1` → массив `Day` с вложенными `Tasks` (задачи, сохранённые в плане, через `day_tasks`). Ответ `null` трактовать как `[]`.
2. `GET /groups/user/1` → массив `Group` — только чтобы подписать группу у задачи. 404 «Группы пользователя не найдены» трактовать как `[]`; ошибка этого запроса не ломает экран (просто без подписей групп).

Текущий день ищется на клиенте: `Day`, у которого локальная дата `Date` совпадает с выбранной датой. Если таких несколько — берётся с наибольшим `DayId`.

`GET /days/:id` **не используется**: он пересобирает список задач «на лету», не сохраняя, и выкидывает выполненные — прогресс дня станет невидим.

| Что показываем | Источник (эндпоинт) | Поле ответа | Формат |
|---|---|---|---|
| Дата в `DateSwitcher` | `GET /days/user/:user_id` | `Day.Date` (RFC3339) | «Сегодня, 24 сентября» / «Вчера, 23 сентября» / «Пятница, 26 сентября»; под ней день недели, если не сегодня/вчера/завтра |
| Подзаголовок «Выполнено 1 из 4» | вычисляется | `Day.Tasks[].Status` | число задач со `Status = 2` / всего в `Tasks` |
| Плитка «задачи в плане» | `GET /days/user/:user_id` | `len(Day.Tasks)` | число + подпись со склонением («4 задачи в плане», «5 задач в плане»). Если `len(Tasks) < AmountOfTasks` — подпись «из 5 запрошенных» вторым рядом |
| Плитка «время на задачи» | то же | `Day.TimeForTasks` (минуты) | `Ч:ММ`: «7:00», «4:30»; `aria-label` словами |
| Плитка «приоритет дня (осталось)» | **вычисляется на клиенте** | `Σ Day.Tasks[].Priority` по задачам со `Status = 1` | «23,2»; `title="Сумма приоритетов невыполненных задач плана"`. Поле `Day.PriorityOfTheDay` из ответа **не используется** (это снимок на момент сборки плана). Когда активных задач нет — «0» |
| Прогресс «Занято времени» | вычисляется | `Σ Day.Tasks[].TimeForExecution` против `Day.TimeForTasks` | «6:45 из 7:00»; заполнение = сумма / TimeForTasks, max 100%. Сумма > TimeForTasks — состояние «Перегруз» |
| Список задач | то же | `Day.Tasks[]` | `TaskRow` в отдельных карточках (`.task-list`) |
| Порядок задач | то же | `Task.Priority`, `Task.Status` | активные по `Priority` ↓, затем выполненные |
| Название, время, дедлайн, прогресс, приоритет | то же | `Task.Name`, `Task.TimeForExecution`, `Task.DeadLine`, `Task.PercentOfCompleting`, `Task.Priority` | как на экране «Все задачи» (см. `TaskRow`); уровень приоритета — относительно максимума среди активных задач **этого дня** |
| Группа задачи | `GET /groups/user/:user_id` | `Group.Name` по `Task.GroupId` | первый факт мета-строки с иконкой папки; нет группы — факт не выводится |
| Соседние дни для стрелок | `GET /days/user/:user_id` | `Day.Date` всех дней | см. «Действия» |

## Компоненты

Из `system.md`: `AppShell`, `AppHeader`, `AvatarButton`, `DateSwitcher`, `SummaryStat`, `ProgressBar`, `SectionTitle`, `TaskRow` (с фактом группы), `Checkbox`, `PriorityIndicator`, `DeadlineLabel`, `PlanForm` (Stepper + TimeInput + пресеты), `Sheet`, `Badge`, `BottomNav` / `SideNav`, `Skeleton`, `EmptyState`, `ErrorState`, `Toast`, `Button`.

Новые компоненты, добавленные для этого экрана в `system.md`: `PlanForm`, `TimeInput`, `Sheet`, `Badge`, `SectionTitle`.

Структура сверху вниз:
1. `AppHeader`: «Задачи на день», подзаголовок «Выполнено N из M», `AvatarButton`.
2. `DateSwitcher`.
3. Три `SummaryStat` в ряд: задачи в плане, время на задачи, приоритет дня (осталось).
4. `ProgressBar` «Занято времени».
5. `SectionTitle` «По приоритету» + ghost-кнопка «Изменить план».
6. Список `TaskRow`.
7. `BottomNav` с активным пунктом «День». `Fab` на этом экране нет — задачи создаются на «Все задачи».

## Адаптивность

- < 960px: как в макете. Плитки сводки — сеткой 3 в ряд; на ширине < 360px — 2 + 1 (третья на всю ширину). `Sheet` выезжает снизу.
- ≥ 960px: `SideNav` вместо `BottomNav`, контент центрирован (`max-width: 720px`); `Sheet` — диалог 420px по центру. Плитки и прогресс остаются над списком (двухколоночную раскладку не делаем — список короткий).

## Требуется от бэкенда

1. **Формирование дня сейчас не работает.** `FillDayTaskListAndCalculatePriorty` запрашивает задачи с `Status = 1`, а в `TaskRepositoryImpl.FindByUserID` из-за бага (`if filter.Status != 0` вместо `filter.GroupId != 0`) добавляется `group_id = 0` → задач нет. Нужно исправить условие.
2. **День без задач.** Если активных задач нет, `FillDayTaskListAndCalculatePriorty` возвращает `nil, nil`, после чего `CreateDay` пытается сохранить `nil`, а `GET /days/:id` отдаёт `null`. Нужно: возвращать день с пустым `Tasks` и `PriorityOfTheDay = 0` (201/200).
3. **Учитывать `TimeForTasks` при выборе задач.** Сейчас план ограничен только `AmountOfTasks`, поэтому легко получается «перегруз». Предложение: брать задачи по убыванию `Priority`, пока суммарное `TimeForExecution` помещается в `TimeForTasks` и число задач ≤ `AmountOfTasks`.
4. **Единицы `TimeForTasks`** — утверждено: минуты (как `TimeForExecution`). Зафиксировать это комментарием в модели `Day` и в `DayCreateRequest` / `DayUpdateRequest`. Формат `Ч:ММ` — только представление на фронте, API остаётся в минутах.
5. **Пересборка теряет выполненные.** `UpdateDay` заменяет `Tasks` только активными задачами — выполненные сегодня пропадают из плана и из счётчика «Выполнено N из M». Предложение: при пересборке сохранять уже выполненные задачи дня и добирать к ним активные.
6. **День по дате.** Удобнее `GET /days/user/:user_id?date=YYYY-MM-DD` (или `/days/today`), чем выбирать нужный день из полного списка на клиенте. Также — запрет второго `Day` на ту же дату (сейчас можно создать дубликаты).
7. **`PriorityOfTheDay` = остаток.** Решено: приоритет дня — сумма `Priority` невыполненных (`Status = 1`) задач плана. Фронт считает его сам из `Tasks`. На сервере желательно считать так же (пересчитывать при выдаче дня / при изменении задач плана) либо не хранить поле вовсе — сейчас это снимок на момент сборки, и он расходится с тем, что видит пользователь.
8. **`Day.Status`** (`StatusDayValid` / `StatusDayExpierd`) нигде не выставляется — фронт определяет «Прошедший день» по дате. Либо проставлять статус, либо убрать поле.
9. Общие для задач пункты — возврат задачи в работу (`status` в `POST /tasks/update/:id`), актуализация `Priority` по времени, `GroupId default:1` — см. `all-tasks.md`.
10. **Пустые списки — 200 `[]`**: `GET /days/user/:user_id` при отсутствии дней сейчас отдаёт `null`.
